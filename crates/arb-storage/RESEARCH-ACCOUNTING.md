# Durable research decisions and virtual accounting

Decision traces are immutable raw observations, addressed by a digest of their complete sealed payload. The worker batches at most 64 traces and 256 KiB under its session-local gate; PostgreSQL checks the current lease, epoch, generation, configuration, experiment and strategy. Every referenced capture must already be admitted in that same session and generation with the same manifest digest. Version 1 uses that manifest digest as the snapshot identity. A changed payload cannot overwrite an existing observation.

Grouping adds a versioned route/size/time-window key while retaining every quote, negative result, rejection, no-route observation and data-unavailable observation. Groups preserve dataset origin. Candidate queries filter QUOTED observations before pagination. Quotes remain CANDIDATE, with unknown external-cost net represented as null; they are not simulations, estimated executable attempts or realized outcomes. Unique opportunity counts include only groups containing quotes. Collection completeness remains UNKNOWN without a proven observation schedule; eligible-attempt and reconciled-transaction counts are unavailable (null), and capture metadata attempts are never included as trading results.

Paper runs freeze their operator/session/network/configuration and initial balances. Creation requires a stopped PAPER session with no pending command and validates token assets against the frozen enabled network allowlist. An operator retry with the same key and payload returns the same run; resetting creates a new run without rewriting prior balances.

Each internal reserve/reconcile command locks the owning worker session and run, validates/replays the complete ordered journal, applies the exact integer reducer, and commits the new immutable event, cursor and audit record atomically. Principal tokens and native fee inventory remain separate. UNKNOWN outcomes retain reservations. Repeated command keys return the original event; changed command payloads conflict. Reservations require current running generation, while positive reconciliation may finish after a fence. No HTTP reservation, settlement, signing or execution endpoint exists.

Run recovery is bounded to 5,000 events and 16 MiB of serialized journal data; commands are bounded to 32 KiB, serialized events to 64 KiB, and initial portfolios to 32 assets. Every outstanding reservation retains one terminal event slot and 64 KiB of journal capacity. New reservations and UNKNOWN markers cannot consume that protected capacity; terminal reconciliation can spend its own allowance. Every projection replays and verifies stored event digests, postings, sequence, initial balances, network and byte totals. Replay applies each command in place to a fresh owned reducer and discards the entire reducer on any mismatch; it no longer clones all prior journal entries at every step. Public command application retains one atomic clone-and-commit, so failure cannot partially change a caller-owned run. History copying during recovery is linear in journal size; this does not establish a production latency or throughput target for a page containing many long runs. This is a bounded research implementation, not an unbounded production accounting index; longer campaigns require reviewed checkpoint/archival support or explicit new runs. Journal sequence values serialize as decimal strings. Financial balances use exact integer strings.

Paper settlement methods are internal model/test primitives until the separate full-transaction simulation and evidence gates exist. A supplied hypothetical outcome does not grant SIMULATED or REALIZED evidence. Paper reservation counts describe virtual budgets, not emitted chain transactions or the raw-capture admission journal.

Migration 0002 is forward-only and preserves migration 0001 checksums and historical rows. The append-only triggers protect ordinary update/delete mistakes; a database administrator remains capable of schema alteration. Use the backup/rehearsal/restore procedure in migrations/README.md, stop/fence writers before recovery, and preserve audit history. Never infer settlement or resume automatically after restart.

Mandatory PostgreSQL tests in tests/paper.rs and tests/decisions.rs cover concurrent capital conflicts, fee-only inventory rejection, durable unknown outcomes, exact replay and conservation, idempotency, immutable initial balances, no-route versus missing-data counts, group windows, pagination after filtering, provenance scope, stale-generation rejection and append-only history. They fail when TEST_DATABASE_URL is absent. Their presence is not a claim of passing CI or market profitability.

Trace page cursors use UUID v7 IDs generated under the session transaction lock. Pages are live queries, not a repeatable-read export snapshot; cross-process clock/commit ordering can change visible continuation results while writers run. The UI must refresh rather than claiming collection completeness from paging. Capture references additionally bind the admitted research attempt's worker epoch. Use an explicitly frozen replay/export dataset for reproducible full-window comparison.

## Collection attempts and interrupted work

Migration 0003 adds immutable collection identities and one terminal transition. Operator, session, network, configuration, experiment, generation, worker identity/epoch, purpose and start time cannot change. A start uses a canonical UUID and scope digest; terminal evidence uses a second digest, bounded reason enums, at most eight captured pools and a monotonic elapsed duration bounded to 24 hours. No raw provider error, endpoint or response body is persisted in this journal. A retried receipt is idempotent only when the entire original payload matches.

Only a RESEARCH batch may atomically finish with DECISIONS_RECORDED; it retains the existing lease, generation, capture and session validation. Each durable decision has at most one collection association, and duplicate observations in a batch are rejected. The receipt exposes the exact observation IDs and count. Any failure to persist the whole transaction leaves the earlier start unresolved and rolls back the candidate inserts. Nonfinancial failure, cancellation or readiness evidence may arrive after STOP or worker replacement through the exact original claim; this path cannot create decisions, refresh a lease, alter the session or admit new work.

A retained IN_PROGRESS row means no terminal evidence was committed. It may represent active work, interrupted work, a crash, or an uncertain delivery. Age and replacement do not convert it to failure. The collection journal is separate from research_attempts and paper reservations; its rows never increment or resolve financial/drain accounting. A complete export of retained database rows is still not a complete historical acquisition schedule, and collection attempt records do not preserve input origin. Never aggregate these operational counts as a market-origin or execution denominator.

The PostgreSQL collection tests exercise committed starts, unknown outcomes, retries, concurrent terminal conflicts, strict reasons and bounds, SQL immutability, operator scoping, atomic rollback, unique decision associations and late telemetry after STOP/worker replacement. They require a real TEST_DATABASE_URL and never silently skip.
